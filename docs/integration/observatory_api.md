# Интеграция с обсерваторным «Диптихом» (комплекс №8)

Обсерваторная автоматика **уже существует** (проект Diptich_hub: REST, MQTT,
ESP32 MCC-1 / Vizor / T-Connect / T-Panel, MongoDB, INDI/ASCOM).
Ядро «Астрокосмоса» не копирует эту систему.

Полной спецификации API в поставке документации «Астрокосмоса» **не было**.
Ниже — **целевой контракт адаптера**, который нужно сверить с реальным
`docs/api_specification.md` обсерватории и поправить пути 1:1.

Клиент: `backend/app/integrations/observatory/client.py`.
Настройки: `OBSERVATORY_API_BASE_URL`, `OBSERVATORY_API_TOKEN`.

## Принципы

1. Ядро — клиент, обсерватория — источник правды по куполу и телескопу.
2. Таймаут запросов (по умолчанию 15 с). Нет «вечного» ожидания slew.
3. Команды с побочным эффектом (открыть купол, slew) — только роль `admin`
   или `educator`, с подтверждением в UI.
4. При 4xx/5xx сценарий ядра переходит в деградацию: видео и голобоксы
   работают, наблюдение помечается как недоступное.
5. Webhook от обсерватории (опционально) на
   `POST /api/v1/observatory/webhook` с секретом `OBSERVATORY_WEBHOOK_SECRET`.

## Ожидаемые операции (логика, не финальные URL)

| Действие ядра | Смысл | Ожидаемый внешний вызов (пример) |
|---------------|--------|----------------------------------|
| Статус | Купол, координаты, метео, камера | `GET /status` или набор GET |
| Открыть купол | Перед наблюдением | `POST /dome/open` |
| Закрыть купол | Конец сценария / тревога | `POST /dome/close` |
| Наведение | RA/Dec или имя объекта | `POST /telescope/slew` |
| Парковка | Безопасное положение | `POST /telescope/park` |
| Кадр/поток | URL RTSP/HTTP для Иллюминатора и Астровизора | `GET /camera/stream` |
| Метео | Ветер, дождь, облачность | `GET /weather` |

Примеры из `docs/context/02_architecture.md` и `modules/08_diptih_OBS.md`
(`POST /api/telescope/slew`, `/api/v1/dome/open`) расходятся — **нужна
сверка с живым OpenAPI Diptich_hub**.

## Минимальный JSON статуса (канон ядра)

Адаптер приводит ответ обсерватории к этой форме, чтобы админка не знала
внутреннюю модель MongoDB:

```json
{
  "available": true,
  "dome": { "state": "open|closed|moving|unknown" },
  "telescope": {
    "ra": null,
    "dec": null,
    "tracking": false,
    "parked": true
  },
  "weather": {
    "wind_ms": null,
    "rain": false,
    "safe_to_observe": false
  },
  "camera_stream_url": null,
  "source_error": null
}
```

## Чего адаптер не делает

- OTA прошивок купола
- Анализ Modbus RTU
- Управление вентилятором MCC-1
- Прямая публикация в MQTT обсерватории
- Обход аварийных блокировок (ветер, дождь)

## Что нужно от владельцев обсерватории

- Актуальный OpenAPI или `api_specification.md`
- Тестовый стенд или mock с теми же путями
- Токен сервисного аккаунта «Астрокосмос» с ограниченными правами
- URL потока камеры, доступный с RPi Иллюминатора/Астровизора в LAN
- Описание webhook (если есть) или подтверждение, что только polling

До получения спецификации эндпоинт ядра возвращает `not_implemented` /
`available: false` и не блокирует разработку админки.
