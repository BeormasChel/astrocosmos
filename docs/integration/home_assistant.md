# Home Assistant — комфорт аудитории

Настольный «Диптих» и сценарии занятий **могут** управлять светом и жалюзи.
Home Assistant для этого нужен как **исполнитель**, не как оркестратор.

## Зачем так

Если педагог запускает занятие в админке, а ребёнок параллельно говорит
«Диптих, выключи свет», оба запроса должны пройти через ядро: права,
журнал, конфликт с открытым куполом, единый undo.

## Поток

```
Настольный Диптих (MQTT event)
        или шаг занятия
                 ↓
        FastAPI (проверка роли)
                 ↓
  integrations/home_assistant
                 ↓
     HA REST / websocket
                 ↓
     свет, жалюзи, проектор
```

Сущности HA задаются в настройках ядра (entity_id), не хардкодятся в прошивке.

## Минимальные сервисы MVP Диптиха

- `light.turn_on` / `light.turn_off` / яркость
- закрыть / открыть жалюзи (`cover`)
- опционально: сцена «занятие» / «уборка»

Купол и телескоп через HA **не** трогаем.

## Конфиг

`HA_BASE_URL`, `HA_TOKEN` в `.env`. Если URL пустой — шаги комфорта в сценарии
помечаются «пропущено», занятие не падает.
