# Дорожная карта MVP «Астрокосмос»

Оценка в **человеко-неделях** одного разработчика, знакомого со стеком.
Параллель фронт+бэк сокращает календарь, но не сумму человеко-недель.

**MVP админки** = контент + сценарии + мониторинг + расписание +
два простых комплекса (часы, настольный Диптих) + контракт Малого Голобокса.
Обсерватория в MVP — **статус read-only** и заглушка команд.
Астровизор (улица) и Большой Голобокс — после MVP.

Итого ядро+админка+первые комплексы: **примерно 16–20 человеко-недель**.

## Этап 0. Репозиторий и инфраструктура — 1 н.

- Git: `main` / `develop`, `.gitignore`, `.env.example`
- Docker Compose: Postgres 16, Redis, Mosquitto, API, worker, frontend
- CI-заготовка: pytest + lint (можно локально, без облака)

**Готово, когда:** `docker compose up` поднимает `/api/v1/health` и оболочку админки.

## Этап 1. Ядро данных и auth — 2 н.

Приоритет: **P0**

- Модели: User, Device, DeviceHeartbeat, ContentItem, Scenario, ScenarioStep, ScheduleSlot
- Alembic, роли admin / educator / attendant
- JWT login, защита эндпоинтов

**Готово, когда:** педагог логинится, видит пустой реестр устройств.

## Этап 2. MQTT и мониторинг — 1.5 н.

Приоритет: **P0**

- Мост paho-mqtt, топики `docs/mqtt/topics.md`
- Регистрация устройства при первом heartbeat
- Дашборд: online/offline/degraded
- Эмулятор устройства (Python-скрипт) для разработки без железа

**Готово, когда:** эмулятор `planet_clock` зелёный на дашборде, через 30 с без heartbeat — серый.

## Этап 3. Админка CMS + сценарии (скелет) — 3 н.

Приоритет: **P0** (главный пользовательский результат MVP)

- CRUD контента (метаданные + загрузка файлов на диск `MEDIA_ROOT`)
- Редактор сценария: упорядоченные шаги «устройство + команда + длительность»
- Кнопки Старт / Стоп, журнал выполнения
- Расписание: cron/datetime → Celery Beat ставит `run_scenario`

**Готово, когда:** педагог создаёт сценарий «подсветка часов 30 с» и ставит его на 11:00.

## Этап 4. Астрономические часы (первый физический контур) — 2 н.

Приоритет: **P0** (самый простой ESP32)

- Прошивка: NTP, FastLED, MQTT command `set_mode`
- Режимы: idle, compare (Земля/Юпитер), retrograde
- Тест: команда из админки меняет анимацию на стенде

**Риск:** питание лент, тайминги WS2812 на ESP32-C3 — закладываем день на стенд.

## Этап 5. Настольный Диптих (RFID + команды, голос урезан) — 2.5 н.

Приоритет: **P0**

- RFID read/write меток, привязка к персонажу в CMS
- Событие `rfid_scan` в ядро, вход сотрудника в админку по UID (опционально в этом этапе)
- Голос MVP: 5–10 фраз Piper по команде сценария, **без** LLM
- STT wake-word — если не успеваем, перенос на этап 5b (+1.5 н.)

**Готово, когда:** запись метки из админки работает; сценарий озвучивает факт о планете.

## Этап 6. Малый Голобокс (адаптер, не Unity-контент) — 2 н.

Приоритет: **P1**

- Контракт HTTP+MQTT, sidecar или Unity-заглушка «открыть раздел N»
- Ядро умеет шаг сценария `maly_golobox.open_section`
- Сам 3D-контент метеорита делается параллельно контент-командой, не блокером ядра

## Этап 7. Иллюминатор (видео) — 2 н.

Приоритет: **P1**

- Агент RPi: VLC, NFS, MQTT
- Пульт ESP32: выбор ролика
- Сценарий ядра переключает Attract / конкретный ролик
- Автономность при обрыве MQTT

## Этап 8. Обсерватория: адаптер — 1.5–2 н. после получения API

Приоритет: **P1** (блокируется спецификацией)

- Маппинг реального OpenAPI → канон `docs/integration/observatory_api.md`
- Админка: статус купола/телескопа/метео
- Команда «безопасная парковка» (не полный slew) — если API позволяет
- Сценарий «Наблюдение за Юпитером» в деградации: без купола всё равно крутит видео

## Этап 9. Тумба RFID — 1.5 н.

Приоритет: **P2** после тумбы как железа

- Агент RPi + считыватель, видео персоналии из CMS
- Переиспользование тех же RFID ID, что пишет настольный Диптих

## Этап 10. Большой Голобокс и Астровизор — после MVP

Приоритет: **P2 / P3**

- Большой Голобокс: тот же контракт, что у малого, плюс RFID учёных
- Астровизор: механика, IP65, RTSP, синхронизация Az/El — отдельный мини-проект ~6–8 н. с железом

## Порядок подключения комплексов (сводка)

1. Эмулятор MQTT (без железа)
2. Астрономические часы
3. Настольный Диптих (RFID, затем голос)
4. Малый Голобокс (адаптер)
5. Иллюминатор
6. Обсерватория (read-only → команды)
7. Интерактивная тумба
8. Большой Голобокс
9. Астровизор

## Зависимости календаря

```
0 ─► 1 ─► 2 ─► 3 ─┬─► 4 (часы)
                  ├─► 5 (Диптих №3)
                  └─► 6 (Малый Голобокс)
         3 ─► 7 (Иллюминатор, нужен NFS)
         8 (обсерватория) стартует, как только есть OpenAPI
```
