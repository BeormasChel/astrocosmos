# Дорожная карта (команда из двух человек)

Оценки — **календарные недели** при работе заказчик + AI в Cursor
(железо и контент — на стороне площадки).

Цель ближайшего этапа: **админка ядра**, которой педагог пользуется без
программиста: обзор, занятия, комплексы 1–7, материалы, расписание.
Развёртывание: `docker compose up`.

## Этап A. Ядро и админка — 3–4 нед.

P0. Данные, роли, MQTT-эмулятор, UI по [`ui_ux.md`](../architecture/ui_ux.md),
CMS метаданных, запуск/стоп занятия, расписание.

**Готово:** педагог с планшета запускает занятие-заглушку и видит семь карточек комплексов.

## Этап B. Иллюминатор — 2 нед.

P0. Pi 5, 4K, NFS, пульт, Attract Mode без ядра.

## Этап C. Часы — 1.5 нед.

P0. MQTT-режимы с админки.

**Стенд:** страница `/clocks` в пульте, команды `astroc/devices/planet_clock/command`.
Прошивка ESP32 — в `microcontrollers/planet_clock/` (лента не обязательна для проверки режимов).

## Этап D. Малый Голобокс — 3 нед.

P0. Киоск React + видеофрагменты + тач. 3D-метеорит: glTF/Three.js или видео из Unity.

**Стенд:** `http://localhost:3001/maly`, команда `open_section`. glTF — позже.

## Этап E. Большой Голобокс + тумба PN532 — 3 нед.

P0. Тот же киоск-стек. RFID тумбы открывает контент учёного на 72".

## Этап F. Настольный Диптих — 2.5 нед.

P1. RFID-программатор PN532, TTS Piper, шаги комфорта через Home Assistant.

## Этап G. Астровизор — 2 нед.

P1. Показ сетевого потока камеры купола. Без механики киоска.

## Этап H. Обсерваторный Диптих — после OpenAPI

P2. Совместно проектируем API; брокер купола остаётся отдельным.
Первый полезный кусок — стабильный URL потока для этапа G.

```
A (ядро) → B (иллюминатор) → C (часы) → D (малый) → E (большой+тумба)
        → F (настольный Диптих) → G (астровизор) → H (купол)
```
