# Runtime голобоксов: видео, тач-GUI и роль Unity

Оба голобокса — Raspberry Pi и прозрачный сенсорный экран.
Посетитель работает **касанием**. Интерфейс должен быть крупным, мгновенным
и «музейным», а не копией десктопной админки.

## Основной путь (рекомендуется)

**Chromium в режиме киоска + React-приложение** на самом Pi.

| Слой | Технология | Зачем |
|------|------------|--------|
| Оболочка | Raspberry Pi OS + Chromium `--kiosk` | Быстрый деплой, тот же стек, что админка |
| UI | React 18, TypeScript, Vite | Тач-кнопки, жесты, состояния |
| Движение | CSS + Framer Motion | Современная интерактивная графика без игрового движка |
| Видео | HTML5 `<video>` (hardware decode на Pi) | Готовые фрагменты разделов |
| 3D метеорита | Three.js / React Three Fiber, модель **glTF** | Вращение пальцем, маркеры слоёв |
| Фон | строго `#000000` | Прозрачность ЖК |
| Связь | MQTT heartbeat + команды ядра | Сценарии педагога |

Разделы Малого Голобокса (строение, падение, история…) — **плейлист видео**
+ тонкий тач-оверлей (кнопки «Назад», маркеры, слайдеры). Тяжёлая физика
удара и полёт над Челябинском не считаются на Pi в реальном времени.

## Unity: студия, не плеер на Pi

Unity плохо живёт как runtime на Raspberry Pi (ARM, GPU, kiosk, обновления).

Имеет смысл оставить Unity **на машине контент-дизайнера**:

1. Собрать сцену метеорита, свет, анимацию падения.
2. Прогнать камеру → экспорт **видеофрагментов** (H.264/H.265) на NFS.
3. При необходимости экспорт **glTF** (статика или короткая анимация) для Three.js.

Так вы не теряете уже запланированную работу в Unity, но не ставите игровой
движок на каждый киоск.

## Альтернативы runtime (если веб не устроит)

| Вариант | Плюсы | Минусы | Когда брать |
|---------|-------|--------|-------------|
| **Godot 4** (Linux ARM) | Настоящий движок, тач, 3D | Тяжелее веба, отдельный пайплайн от админки | Нужны сложные жесты/физика на Пи |
| **Flutter** | Отличный тач, 60 fps UI | 3D слабее, два языка в команде из двух человек | Если Three.js не потянет UI |
| **Qt/QML** | Нативно на Pi | Дольше собирать UI, меньше кадров | Жёсткий офлайн без Chromium |
| Unity player на Pi | Привычный редактор | Не опираться: нестабильно и медленно | Не рекомендуется |

Для команды из двух человек **веб-киоск + Unity как DCC** даёт максимум
переиспользования с админкой и предсказуемый деплой (`docker` на сервере,
systemd + Chromium на Pi).

## Требования к тач-GUI (оба голобокса и иллюминатор)

- Цель касания не меньше **64×64 px**, на 72" — ещё крупнее.
- Один главный акцент на экран (не сетка из 20 кнопок).
- Idle через 60 с → привлекающий ролик, первое касание сразу в меню.
- Нет системного курсора, нет адресной строки браузера.
- Тексты короткие, научные термины — по нажатию, не сразу стеной.
- Обратная связь на касание < 100 мс (подсветка, звук-клик).
