## Описание проекта

Диптих - комплексная система автоматического управления обсерваторией, включающая:
- **Устройства на ESP32**: Vizor-1, Vizor-2, Vizor-3, T-Connect, T-Panel, MCC-1
- **Веб-приложение Diptich_hub**: Backend (REST API, MQTT) и Frontend (веб-интерфейс)
- **Драйверы оборудования**: PLK_EKF, преобразователь частот
- **Инфраструктура**: MQTT брокер, база данных, конфигурации

## Компоненты системы

### Устройства ESP32

Все устройства ESP32 интегрированы с компонентами Фазы 1 и 2:

**Общие компоненты (интегрированы во все устройства):**
- ✅ **WatchdogManager** - Многоуровневый watchdog для автоматического восстановления после сбоев
- ✅ **PriorityQueue + MQTTPriorityAdapter** - Приоритетные очереди сообщений с QoS гарантиями
- ✅ **ConnectionManager** - Адаптивный менеджер соединений с автоматическим переключением каналов
- ✅ **GracefulDegradation** - Система graceful degradation для сохранения функциональности при нехватке ресурсов
- ✅ **ConfigManager** - Удаленный менеджер конфигураций с версионированием и откатом
- ✅ **Logger** - Расширенное логирование
- ✅ **MemoryManager** - Мониторинг памяти

- **MCC-1** (Motor Control Center): Компонент системы для управления редукторным мотором (Reduktor_3). Включает плату **Lyligo T3S3 V1.2 ESP32-S3 LoRa2.4G SX1262** для взаимодействия с частотным преобразователем ESQ-760-4T-0015 через Modbus RTU, мониторинга и управления температурным режимом внутри шкафа управления. Шкаф управления содержит: плату T3S3, частотный преобразователь ESQ-760-4T-0015, вентилятор, датчики температуры. **Поддерживает автономный режим** при потере связи с сервером (остановка мотора, включение вентиляции). ✅ **Интегрированы все компоненты Фазы 1 и 2**.
- **Vizor-1, Vizor-2**: Устройства визуального контроля с определением точного направления по азимуту (используют фильтр Мэджвика + Расширенный фильтр Калмана). **Поддерживают автономный режим** с локальным логированием данных. ✅ **Интегрированы все компоненты Фазы 1 и 2**.
- **Vizor-3**: Устройство визуального контроля и мониторинга состояния обсерватории. **Поддерживает автономный режим**. ✅ **Интегрированы все компоненты Фазы 1 и 2**.
- **T-Connect**: Устройство подключения с поддержкой Modbus RTU/TCP (RS-485). **Поддерживает автономный режим** с буферизацией Modbus данных. ✅ **Интегрированы все компоненты Фазы 1 и 2** + **PLCCommandQueue** для управления очередью Modbus команд.
- **T-Panel**: Панель локального управления с интерфейсом. **Поддерживает автономный режим** с отображением статуса "Автономно" на дисплее. ✅ **Интегрированы все компоненты Фазы 1 и 2**.

### Веб-приложение Diptich_hub (Главный центр управления)

**Diptich_hub** является головным устройством всей системы и главным центром управления.

- **Backend**: REST API, MQTT клиент для связи с устройствами (с поддержкой TLS/MQTTS), база данных, бизнес-логика, отслеживание всех MQTT клиентов, анализатор пакетов Modbus RTU, модуль управления NFC картами доступа, **Health Check система** (проверка всех компонентов), **OTA менеджер** (централизованное управление прошивками), **Журнал обслуживания** (предсказательное обслуживание), **Защита от ошибок** (безопасные цепи и подтверждения), **Машина времени** (воспроизведение исторических данных), **Correlation ID** (сквозное логирование), **Управление MCC-1** (контроль вентилятора), **OpenCV обработка** (детекция апертуры), **Расширенный мониторинг** (GPS, LoRa, LED, вибромотор, кнопки для всех устройств). ✅ **Обновлено** - поддержка всех новых метрик от компонентов ESP32
- **Frontend**: Веб-интерфейс для управления системой, дашборд мониторинга, настройки, страница анализа пакетов Modbus RTU, управление NFC картами доступа, **Управление MCC-1** (виджет с drag-and-drop), **Расширенный мониторинг устройств** (GPS, LoRa, LED, вибромотор, кнопки в DeviceDetail), **Отображение апертуры** (процент открытия люка в Observatory), **Поддержка темной темы** для всех новых компонентов

### Драйверы

- **PLK_EKF**: Драйвер для работы с оборудованием PLK_EKF
- **Преобразователь частот**: Драйвер для управления преобразователем частот

## Коммуникация

Система использует протокол **MQTT** для связи между компонентами:
- Все устройства ESP32 подключаются к MQTT брокеру
- **TLS/MQTTS** поддержка для безопасной связи (настроено в Backend, подготовлено для ESP32)
- Использование **OpenMQTTGateway** для объединения различных технологий и протоколов в единую прошивку
- Backend подписывается на топики устройств и управляет ими
- **Отслеживание всех MQTT клиентов** в веб-приложении (на основе HiveMQ MQTT Message Log Extension)
- **Correlation ID** передается через все MQTT сообщения для сквозного логирования
- Real-time обновления через WebSocket для frontend
- **Modbus RTU/TCP** поддержка через компактную библиотеку для ESP32 и шлюз Modbus RTU (RS-485) — MQTT
- **Автономный режим** для всех ESP32 устройств при потере связи с сервером (>5 минут)

Подробнее о протоколе: [docs/mqtt_protocol.md](docs/mqtt_protocol.md)

## Технологии и библиотеки

### ESP32 компоненты (Фаза 1 и 2):
- **WatchdogManager**: Многоуровневый watchdog для автоматического восстановления после сбоев
- **PriorityQueue + MQTTPriorityAdapter**: Приоритетные очереди сообщений с QoS гарантиями
- **ConnectionManager**: Адаптивный менеджер соединений с автоматическим переключением каналов (WiFi, BLE, LoRa)
- **GracefulDegradation**: Система graceful degradation для сохранения функциональности при нехватке ресурсов
- **ConfigManager**: Удаленный менеджер конфигураций с версионированием и откатом
- **PLCCommandQueue**: Очередь команд для ПЛК (T-Connect) с приоритизацией и конфликт-разрешением

### Другие технологии:
- **OpenMQTTGateway**: Объединение различных технологий и протоколов в единую прошивку ESP32
- **ESP32-OTA-Pull**: Технология OTA-обновлений для ESP32 устройств
- **Фильтр Мэджвика + Расширенный фильтр Калмана**: Определение точного направления по азимуту для Vizor-1 и Vizor-2
- **Modbus RTU/TCP**: Компактная библиотека для ESP32 (nanoMODBUS, esp-modbus-mqtt)
- **Анализатор Modbus RTU**: Инструмент для анализа пакетов Modbus RTU в веб-приложении
- **Мониторинг Orange Pi**: Python скрипт для считывания системной статистики и публикации в MQTT
- **NFC карты доступа**: Модуль для управления NFC картами NXP Mifare DESFire EV1 через PN532, вход в систему по карте, управление правами доступа

# Комплекс №8: Система управления обсерваторией «Диптих»

## Логический блок
Автоматизация астрономической обсерватории: управление куполом, телескопом, камерами, климатическими системами.

## Описание оборудования (существующее)
- Автоматический купол с приводом (электродвигатель, концевики, датчики положения).
- Монтировка телескопа с поддержкой ASCOM/INDI (например, Sky-Watcher EQ6 или Celestron CGX).
- Астрономическая камера (ZWO ASI 1600MM или аналогичная) с фильтрами.
- Комплект датчиков: анемометр, датчик дождя, термогигрометр.
- Набор ESP32-контроллеров, размещённых в куполе, управляющих двигателями, считывающих датчики, управляющих питанием.
- Отдельный сервер (или мощный RPi) внутри обсерватории, на котором работает веб-приложение управления.
- Бесперебойное питание.

## Принцип работы (интеграция с общим проектом)
Система управления обсерваторией уже функционирует и имеет собственное веб-приложение. В рамках проекта «Астрокосмос» она интегрируется в единое ядро через REST API:

- Общее ядро отправляет команды на эндпоинты обсерваторного приложения (например, `POST /api/v1/dome/open`, `POST /api/v1/telescope/slew?ra=...&dec=...`).
- Обсерваторное приложение выполняет команды, управляет ESP32, отслеживает состояние и возвращает статус.
- Ядро может запрашивать текущие показатели (состояние купола, координаты телескопа, изображение с камеры) через GET-запросы.

## Интерактивные сценарии (в рамках общего проекта)
- **«Реальное наблюдение»** – по запросу из общей админки система наводится на заданный объект, открывает купол, включает камеру и транслирует изображение на другие экраны.
- **«Автоматическая парковка»** – при сигнале тревоги (сильный ветер, дождь) ядро отправляет команду закрыть купол и увести телескоп в безопасное положение.
- **«Метео-мониторинг»** – данные датчиков отображаются в общей админке и могут использоваться для принятия решений о проведении наблюдений.

## Технические детали интеграции
- **API протокол:** REST (JSON) через HTTPS.
- **Документация API:** предоставляется разработчиками обсерваторной системы (должна быть доступна для интеграции).
- **Схема обмена:** синхронные запросы с таймаутами, асинхронные уведомления через webhook или MQTT (если поддерживается).
- **Безопасность:** аутентификация по токену (API key), предоставленному ядру.

## Образовательный потенциал
- Демонстрация современных методов автоматизации в астрономии.
- Понимание работы телескопа и датчиков.
- Связь теории (уроки) с практическими наблюдениями.

## Примечание
Эта система не разрабатывается с нуля – она уже существует. Задача интеграции – обеспечить взаимодействие с единым ядром для совместных сценариев.
