# Архитектура проекта «Астрокосмос» (с разделением двух Диптихов)

## Общая концепция

Система представляет собой **распределённую гетерогенную сеть устройств**, объединённых в защищённую локальную сеть (WiFi/Ethernet) с фиксированными IP-адресами. Центральным элементом является **сервер** (единое ядро), который управляет контентом, расписанием, сценариями и мониторингом всех подключённых устройств. В проекте две независимые подсистемы с названием «Диптих»:

1. **Настольный помощник «Диптих»** – работает как клиент в сети, управляется через MQTT от сервера, имеет свои ESP32 (микрофон, динамик, RFID).
2. **Система управления обсерваторией «Диптих»** – представляет собой уже развёрнутую систему со своим веб-приложением и ESP32-блоками в куполе. Она интегрируется в общее ядро через REST API (или MQTT) как внешняя система.

Все устройства делятся на категории:
- **Сервер** – хранение данных, бизнес-логика, администрирование.
- **Одноплатные компьютеры (Raspberry Pi)** – управление интерактивными комплексами с экранами и видео.
- **Микроконтроллеры (ESP32)** – для настольного Диптиха, астрономических часов, а также в составе обсерваторной системы (управление куполом, двигателями, датчиками).
- **Телескоп и аксессуары** – управляются через систему управления обсерваторией.

## Коммуникационные протоколы

1. **REST API (HTTP/HTTPS)** – используется для обмена данными между сервером и веб-приложениями (общая админка, а также внешнее веб-приложение обсерваторного Диптиха). Также для загрузки контента и получения статусов.
2. **MQTT (publish/subscribe)** – основной протокол для управления устройствами реального времени (настольный Диптих, часы, механизмы Астровизора). Для обсерваторной системы MQTT может использоваться внутренне, но внешнее взаимодействие с ядром происходит через REST API.
3. **NFS (Network File System)** – для доступа к медиа-файлам (видео, 3D-модели) с сервера на RPi.
4. **Интеграция с обсерваторной системой** – через API-шлюз: ядро отправляет команды (например, открыть купол, навести телескоп) на внешнее веб-приложение обсерваторного Диптиха, которое уже управляет своим оборудованием.

## Компоненты системы (детализация)

### 1. Серверное ядро
- ОС: Ubuntu Server 22.04 LTS
- БД: PostgreSQL
- Бэкенд: FastAPI (Python)
- Фронтенд админки: React + TypeScript
- Брокер: Mosquitto (MQTT)
- Планировщик: Celery + Redis
- Файловое хранилище: SSD, общая папка `/media/content` по NFS.

### 2. Raspberry Pi (клиентские устройства)
- **Малый Голобокс (RPi 5)** – сенсорный экран 21.5", 3D-модели.
- **Большой Голобокс (RPi 5)** – сенсорный экран 72", RFID, видео с AI-аватарами.
- **Иллюминатор (RPi 4)** – воспроизведение 4K-видео.
- **Астровизор (RPi 4/5)** – управление киоском, обработка изображений с камеры телескопа.
- **Интерактивная тумба (RPi 5)** – сенсорный экран 32", RFID.

Все RPi подписаны на MQTT-топики, монтируют NFS-шару.

### 3. ESP32 (микроконтроллеры)
- **Настольный Диптих** – ESP32 с микрофонной решёткой, динамиком, RFID-считывателем.
- **Астрономические часы** – ESP32 для светодиодных лент WS2812.
- **Астровизор (механика)** – ESP32 для управления шаговыми двигателями поворотного механизма.
- **Обсерваторная система** – уже существующие ESP32 (управление куполом, монтировкой, датчиками) – не разрабатываются заново, управляются через API обсерваторного приложения.

### 4. Система управления обсерваторией «Диптих»
- Это самостоятельный программно-аппаратный комплекс, который включает:
  - Веб-приложение (админка) для управления куполом, телескопом, камерами.
  - Набор ESP32-контроллеров, соединённых через WiFi/Ethernet с сервером этой системы.
  - Драйверы для управления монтировкой (INDI/ASCOM).
- Взаимодействие с общим ядром: ядро отправляет HTTP-запросы к API обсерваторной системы (например, `POST /api/telescope/slew`). Обсерваторная система выполняет команду и возвращает статус. Ядро может также запрашивать текущее состояние (открыт ли купол, координаты телескопа, изображение с камеры).

## Взаимодействие (пример сценария с обсерваторией)

1. Педагог в общей админке выбирает сценарий «Наблюдение за Сатурном».
2. Ядро отправляет запрос на API обсерваторной системы: `open_dome()`, `slew_to_saturn()`.
3. Обсерваторная система выполняет действия, подтверждает выполнение.
4. Ядро запускает сопутствующие сценарии на других комплексах (видео на Большом Голобоксе, подсветку на часах, трансляцию изображения на Иллюминатор).
5. Настольный Диптих озвучивает информацию о Сатурне.
6. Все статусы отображаются в общей админке.

## Безопасность и интеграция
- Все внешние API защищены токенами.
- Обсерваторная система имеет собственные механизмы безопасности (датчики ветра, аварийная остановка), которые дублируются на уровне ядра (ядро может отправить команду экстренного закрытия при получении сигнала тревоги).
